# 自定义 GATT 设定值控制器（Vue 3 + TypeScript + Web Bluetooth）

浏览器页面对接一个演示蓝牙控制器，修改其设定值。页面严格区分三类数据：

- **草稿值**：只存在于页面输入框中，命令未获设备回执前绝不是设备值；
- **已确认值**：只来自对「信息特征」的实际读取，或被绑定 commandId 的回执确认后经信息特征复核；
- **未决结果**：一条命令从“写入中 → 字节已写入 → 已确认/未采纳/结果未知”的完整生命周期。

## GATT 协议（自定义服务）

| 对象 | UUID（`…` 省略公共基址 `-0000-1000-8000-00805f9b34fb`） | 属性 | 载荷 |
| --- | --- | --- | --- |
| 服务 | `0000a000-…` | — | — |
| 信息特征 | `0000a001-…` | Read | deviceId(16B ASCII) + bootId(u64) + revision(u32) + value(i32)，共 32B，大端 |
| 命令特征 | `0000a002-…` | Write | commandId(u32) + expectedRevision(u32) + newValue(i32)，共 12B |
| 回执特征 | `0000a003-…` | Read + Notify | commandId(u32) + status(u8) + revision(u32) + value(i32) + bootId(u64)，共 21B |

status：`0` 已采纳 / `1` 修订冲突 / `2` 越界 / `3` 拒绝。固件仅在 `expectedRevision`
等于当前修订且值在 `[-100, 100]` 时采纳，并令 revision +1。回执特征保存最近一条回执。

## 关键正确性规则

1. `writeValueWithResponse` 完成**只表示字节已写入**；采纳以绑定 commandId 的回执为准。
2. 同时最多一个未决命令；“结果未知”的命令必须由用户手动关闭后才能再发，**绝不自动重发**。
3. 断线发生在写入过程中或回执到达前 → 未决命令标记为**结果未知**。
4. 重连 = 重新连接 + **重新发现服务和特征** + 重新订阅通知，再读取信息特征与设备保存的最近回执；
   只有同设备、同 commandId 的已保存回执才用于对账。
5. 查不到匹配回执时：保持结果未知，**不自动重发、不宣称失败**，由用户手动决定。
6. 旧通知（断线后迟到、旧会话、bootId 不匹配、commandId 不匹配、来自其他设备）一律丢弃，
   **不能改写当前设备的确认值**。

## 模拟适配器（无需任何硬件即可验收）

与真实适配器实现同一 `ControllerAdapter` 接口，内置内存“固件”和场景：

- 正常 / **通知先到**（通知早于写事务 resolve）/ **写入后断线**（命令已执行、回执随链路丢失）/
  重启且保留回执 / **重启且回执遗失** / 修订冲突 / 越界；
- 随时注入：他端改值、设备重启（保留/清空回执）、旧会话迟到通知、冒充其他设备的通知。

真实连接模式有独立的“选择并连接真实蓝牙设备…”用户入口；API 不可用时页面明确提示
（需 Chromium 桌面浏览器 + https/localhost）。

## 运行

```bash
npm install
npm run dev      # 打开 http://localhost:5173
npm run build    # 类型检查 + 构建
```

## 建议验收路径

1. 模拟模式连接 SIM-A，发送 37：观察“写入中 → 字节已写入 → 已确认”，已确认值只在回执后更新。
2. 场景切「通知先到」再发送：回执在写完成前到达，最终仍正确确认。
3. 场景切「写入后断线」，发送 → 命令变“结果未知” → 点「重连」：重新发现服务、读信息特征
   与设备保存回执，对账为已确认（回执来自断线前 boot）。
4. 场景切「重启（回执遗失）」重发 → 重连：读不到回执，结果保持未知，无自动重发；
   手动读取可看到设备实际值，再手动决定是否发起新修改。
5. 切换 SIM-B 连接，点「注入冒充其他设备的通知」与「注入旧会话迟到通知」：SIM-B 的确认值不变，日志显示通知被丢弃。
